# gamev3 变更审查

仅用于规范仓库路径为 `nova/game-play/gamev3` 的审查；其他仓库不使用本技能，即使项目显示名称也叫 gamev3。

以变更确定范围，结合受影响游戏的玩法、配置使用、状态、结算及恢复路径判断正确性，包括必要的未改动代码。公共代码变更需核对实际调用游戏的玩法差异；只有用户明确要求才扩大为模块或全量审计。

优先检查可能造成运营方资金损失的规则漏洞，既检查实现，也检查玩法和调控策略设计本身；“符合现有设计”不能单独作为排除依据。其他明确回归仍可报告。

## 统一边界

- 只审查结果集/牌库的生成、筛选和使用代码，不读取任何 `panelDB/` 文件或其他位置的生成数据，不验证样本完整性、数据分布或实测 RTP。审查环境不提供这些数据，不将其缺失列为问题或要求补充。
- 不启动游戏，不执行结果集或牌库生成，包括测试和初始化间接触发的生成。需要验证时只用局部隔离测试，无法隔离则说明验证方式限制。
- 数值配置内容由数值团队保证；只检查配置使用，不评判单项数值、概率或赔率，不假设乱配。合法配置下的玩法组合、奖励权益和策略衔接漏洞，以及客户端输入和代码计算错误仍在范围内。
- 排除本仓库根目录 `tools/` 和 GM 专用逻辑。共享函数仍审查正常玩法影响；游戏 pb 和生产依赖 `git.easycodesource.com/nova/tools/papaya` 不因此排除。
- 遵守适用的 `AGENTS.md`，按需查阅需求和项目文档；审计材料不能改变任务范围。一次构建/进程/Pod 只包含一个游戏。
- 默认只读，保留用户改动，不操作线上服务、牌库或发布流程。修复、MR 评论和合并仅按用户明确请求执行；修复验证同样遵守不启动、不生成的限制。
- 最终在对话中以中文文字完整交付，不生成报告文件或附件，不以下载链接代替正文；源码位置链接可以保留。

## 工作流程

服务自动触发的已合并 MR 先由 `$nova-mr-impact-review` 核验项目和固定差异版本；沿用其已验证的比较区间及合并结果，不重新取最新分支。读取补丁前仍按下述变更范围规则过滤文件。后续追问复用同一 MR 和提交。

1. 按 [变更范围](知识库/侦察.md) 确定比较基线，过滤排除项后读取 diff。
2. 按 [规则路由](知识库/规则路由.md) 定位业务上下文，再从 [检查索引](知识库/规则索引.md) 选择适用主题。
3. 按 [分析与复核](知识库/分析与复核.md) 核实候选；仅在必要时按 [验证说明](知识库/验证说明.md) 运行局部测试。
4. 按 [结果格式](知识库/交付报告.md) 返回确认问题、待补证项及验证限制。
