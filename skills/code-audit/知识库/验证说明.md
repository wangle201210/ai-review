# 局部验证

仅在静态证据不足且测试有助于判断时验证，不要求每项写测试。遵守入口的执行边界：

- 明确预期行为、初始状态、操作序列及金额/次数/状态断言，预期来自已确认的需求或契约。
- 复用现有局部用例，或用少量手工构造的内存对象、fake/mock 测试可疑函数。先检查目标包和依赖的 `init`、`TestMain`、setup 及调用链；`-run` 不会跳过初始化。不能依赖真实账户、资金、PanelDB 或外部服务；不得读取生成文件、调用生成器构造测试数据或做分布统计。
- 确认无启动和生成副作用后，用 `GOWORK=off go test <目标包> -run '^<用例名>$' -count=1`；需要时加单游戏 tag 或 `-race`。新增复现代码优先放在临时副本。
- 不执行 `make run/rebuild/test/test-games/verify`、游戏入口 `go run`、游戏二进制或 `go test ./...`；不设置 `GAMEV3_NUMERIC_TEST=1`，不下载、重建或同步牌库。限制同样适用于临时副本和小规模生成。
- 记录实际命令、版本、断言与结果：已复现、未复现、环境受阻或未执行。未复现不等于不存在；结果推翻假设时更新结论。纯编译、局部单测或 `-race` 只证明各自覆盖的内容，不证明全部并发路径正确；生成数据和分布不属于验证目标，不单列为待补证项。
