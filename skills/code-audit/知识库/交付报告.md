# 审查结果格式

按严重度排序；同等级优先呈现资金损失问题。同一根因合并，列出实际核实的影响路径。不得把一般稳定性问题无依据地升级为资金漏洞。

## 每个问题

- **标题**：`[P1][BUG] 简述问题`；安全漏洞标 SEC，业务/可靠性问题标 BUG。
- **位置**：尽量定位到相关 diff，源码链接注明行号；删除块注明 base 位置。
- **说明**：简述触发条件、变更造成的前后差异、影响和修复方向。资金问题说明玩家操作、成本、奖励变化与损失链路，并区分设计缺陷和实现错误。
- **证据**：关键调用链或实际测试结果，避免粘贴大量源码及日志。

P0 为需立即处置的重大阻断，P1 为高影响、应优先修复，P2 为一般明确缺陷，P3 为低影响缺陷；按影响和前提评级。

## 回复顺序

1. 已确认问题；没有时写“在本次变更范围内未发现可确认的问题”。
2. 影响结论的待补证项，与确认问题分开。
3. 简短说明 MR/提交、base/head 或工作区基线、实际覆盖与排除项、测试和重要限制。全部变更被排除时说明无范围内内容。

不以“已批准”“可以安全合并”或“全项目安全”代替技术结论；不为凑数量添加风格或无关重构建议。涉及账户、凭据和日志时脱敏。
