# G-REQUEST：请求与资金归属

仅在变更涉及请求字段、消息注册或用户/商户上下文时检查，重点追踪对扣费、奖励和调控策略的影响，不展开通用鉴权、参数穷举或资源耗尽审计。

- **请求与扣费语义**：客户端下注、购买类型等字段是否被正确解释；类型转换、字段映射或协议变更是否造成扣费金额与奖励计算基准不一致。协议字段号/语义变化按实际业务影响判断。
- **消息与业务入口**：消息是否绑定到正确的处理函数和状态包装器，是否误走无需扣费的路径。具体重复执行与状态推进检查见 [结算与状态](结算与状态.md)。
- **资金归属**：请求中的标识是否错误覆盖服务端用户、商户或房间上下文，导致扣款、派奖、奖池或回合记录串用；只追踪与本次变更相关的资金路径。
- **调控身份**：普通玩家是否因字段误用、上下文复用或分支变化，被错误识别为内部/豁免账号，从而绕过本应生效的扣费或调控策略。既有合法豁免规则本身不作为问题。

沿实际 `room.Register`、`app.HandleStateReq` 及嵌入的 `AppContext` 核对已有控制，不要求游戏 Handler 重复实现框架校验。只有正常玩家可达且有明确资金影响的路径才作为本专题问题；本地验证方式统一见 [验证说明](../../验证说明.md)。
