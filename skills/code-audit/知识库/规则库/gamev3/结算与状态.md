# G-RULE / G-MONEY / G-STATE：玩法规则、调控策略与结算

## G-RULE：可能导致资金损失的玩法与调控策略漏洞

检查本次变更影响的以下关系：

- **成本与权益**：普通下注、购买、免费和 Bonus 的获取成本、奖励基准及次数是否配套；切换下注额、房间或玩法后，能否把低成本获得的权益按更高基准兑现。
- **规则组合**：累计进度、触发奖励、追加次数、退款和回合恢复是否允许重复领取、保留不该保留的权益，或形成付出成本与所得收益不相称的可重复路径。
- **策略选择与覆盖**：普通、购买、免费、Bonus 和自动完成路径选用的调控策略、控制等级及牌库是否符合各自资金约束；实际策略过滤、跳过条件、优先级和切表流程是否留下可利用缺口。沿真实依赖核对策略职责，不要求所有玩法套同一策略。
- **策略衔接**：调控决策使用的下注、累计收益、回合和用户状态是否与实际扣费及结算一致；切换或恢复是否重置控制状态却保留奖励权益，多个策略叠加或覆盖是否意外放大收益。

报告须给出可达的操作序列、成本与奖励/权益变化、失效的资金约束及本次变更的因果关系。可证明确定性损失时列金额关系；涉及期望收益时仅使用代码与已明确的规则做分析，计入全部成本、概率和失败结果；无法据此证明则不确认套利，不索取或生成数据来补做分布/RTP 验证。正常中奖、明确接受的促销成本或合法策略豁免本身不等于漏洞，但需要核对是否能超出预期范围反复获利。

## G-MONEY：金额与幂等

定位 `user_do`、`spin`、`settle`、`event`、`bag` 及实际扣费、AddAward、End、回合记录和公共依赖实现，按受影响路径核对“校验 → 扣费 → 定奖 → 奖池副作用 → 派奖 → 持久化 → 通知”的实际顺序，不假设所有游戏顺序一致。

检查：

- 金额、赔率、单线倍率、总下注和购买扣费的单位；奖励下注基准和扣费金额不能混用。本项目结果集 scope/结果赔率按单线理解，但其他字段必须追踪各自定义，不随意乘除线数。
- 合法数值配置和实际请求/状态路径下，代码的整数乘加、类型转换、取整顺序及输入上限处理是否导致金额错误；不构造超出配置契约的数值来报告溢出，不能仅因使用 float 就判资金漏洞。
- 普通/免费/Bonus/购买中的单次、阶段和整局累计是否重复计算；递归传播 AllAward、JP 增量和最终 AddAward 是否重复应用。
- 扣费失败、超时但结果未知、写记录失败、派奖失败时的重试/补偿。证明同一回合或交易标识是否贯穿上下游，不能只看到本地重试就认定重复扣款。
- 客户端重发、回调重复、重连、自动完成是否共享去重或状态门槛；先追踪底层幂等键和持久化，不以未见本地幂等表为漏洞。
- 定奖重试、模拟选择或失败路径是否提前消耗奖池、累计奖励或改变余额。

## G-STATE：状态、跨局清理与恢复

核对受影响状态转换对应的消息、自动动作、扣费条件、剩余次数、NextState 和回合结束标记；链路复杂时再画状态表。

- 分别检查首次触发、免费中追加、普通随机、购买和断线自动完成，不将首次 Scatter 条件套用到免费追加。
- 购买失败是否清理购买标记和扣费参数；下一次普通下注能否读到失败残留状态。
- 免费/Bonus 次数递减、追加、阶段切换是否一致；结束记录和通知不能早于必要持久化造成不可恢复状态。
- 重连从保存快照恢复时只完成尚未执行的步骤；重连本身不重置去重依据，不重复扣费、派奖或重抽结果。
- 通知失败、断线、取消和进程关闭与回合操作交错时，是否能通过已有恢复机制收敛。
- 表现盘面与结算结果是否分离，纯表现随机过程是否意外改变定奖或玩法状态。

### 跨局状态残留

沿“前一局写入 → 结束/失败清理 → 下一局初始化 → 首次读取”核对相关字段，不能只看存在 Reset 方法就认为已清理：

- 购买标记、下注/奖励基准、累计奖励与 JP 增量、免费/Bonus 次数、盘面及结果指针、NextState、记录标记、配置快照和本局策略选择是否按生命周期重置。检查实际清理调用、顺序及覆盖字段，尤其是新增字段、ExtBag 和复用的 RoomContext。
- 正常结束、购买或扣费失败、断线自动完成和恢复后的结束路径是否最终进入正确清理；旧缓存、共享切片/map 或延迟回调是否可能把上一局状态重新写入下一局。
- 按规则应跨局保留的累计进度、用户级调控统计等不能误清。区分局内子阶段、未完成局的重连恢复和真正的新局，避免清理过早导致奖励丢失，或清理过晚导致重复派奖/错误策略。

必要时用同一上下文连续执行两局的局部测试：第一局设置相关状态并结束或失败，第二局切换下注额/玩法，检查初始字段与扣费、奖励、策略选择是否仅取本局应有状态。使用手工对象和 mock，不启动游戏或调用生成流程。

**排除与验证**：框架串行化可以排除部分并发假设，但不能直接排除顺序重复消息。合法的免费追加或内部账号差异不能认定作弊。用小型状态序列、扣费失败和恢复快照验证关键副作用次数。
