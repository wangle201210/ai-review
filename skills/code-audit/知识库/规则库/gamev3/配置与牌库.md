# G-CONF / G-PANEL：配置使用与牌库

## G-CONF：配置使用和快照

定位目标游戏 `conf`、`cacheConf`/game_cache、公共 `configset`、`lifecycle`、`panelcache`，检查实际读取链而非只看 TOML 解析结构。

- 字段映射、单位换算、数组索引和玩法/版本选择是否正确。
- 各玩法配置是否实际参与抽样与计算；已提供配置是否被硬编码或默认值覆盖。只见结构体字段不能证明配置生效。
- 单局快照的创建、持有和释放时机；跨普通/免费/Bonus 状态时是否错误混用热更新前后配置。
- 共享配置指针、切片、map 是否会被热更新或计算修改；读取过程中是否观察到部分发布状态。
- 商户、房间与版本键是否完整，默认配置回退会否把其他商户的规则误用于当前商户；共享默认值如为明确设计则不报隔离缺陷。
- 缓存 Ready/Load/Save/Initialize、完成标记与发布顺序、失败重试和空商户预加载是否一致。公共牌库就绪后不按商户版本重复生成可能是项目设计，不作为当然缺陷。

追踪配置来源 → 字段映射 → 发布/快照 → 运行时消费。

## G-PANEL：生成、筛选和使用逻辑

- 通过代码核对生成与筛选分类、结果集 scope/赔率单位、策略门槛、Scatter/Bonus 优先级以及游戏差异；不检查实际生成数据或分布。
- 正常玩法代码是否按配置实现补图、抽样次数和累计概率区间，是否读错权重、漏用配置或错误重分配权重。重试是否消耗源数据或执行真实结算副作用。
- 共享牌库结果被使用后是否原地修改赔率、金额、图标或子局结果，污染其他回合；独立反序列化的结果不强制深拷贝。
- 奖励和表现派生是否分离；表现盘面或通知不应重新决定金额。普通、购买和免费追加路径分别核实。
- 代码是否选错牌库版本、筛选条件错误排除按规则应保留的结果或提前发布完成状态；不凭假设配置/牌库缺失要求增加兜底，不通过调整数值或版本号掩盖代码误用。
