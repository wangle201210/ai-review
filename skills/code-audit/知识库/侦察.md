# 变更范围、基线与上下文

## 确定比较对象

记录 MR/PR 标识（若有）、仓库、目标分支/base、源分支/head、具体提交 SHA 及工作区状态。基线按以下规则选取，不把上次审计版本或 main 当作固定默认：

1. **MR/PR**：先读取用户给出的 MR 元数据和变更文件列表，记录本次 diff 对应的 base/head SHA，过滤 tools 后再获取补丁。审查期间固定这些 SHA；MR 更新后重新确认差异，不能混用不同版本。使用已有连接器或 CLI 获取。源分支不是当前 HEAD 时使用指定提交或隔离只读副本，不混入本地未提交修改。
2. **分支比较**：使用用户指定的目标分支，计算 `git merge-base <target> <head>`，审查合并基点到 head 的差异；等价于 `git diff <target>...<head>`。记录基点 SHA。不要将源分支的 upstream（常是同名远端分支）误当 MR 目标分支。
3. **指定提交/区间**：普通单提交比较父提交与该提交，区间按用户给出的两端；根提交比较空树。合并提交需明确父提交语义或使用 MR 基点，不能猜测比较对象。
4. **当前未提交改动**：比较 HEAD 与工作区，包含暂存和未暂存变更；另列相关未跟踪源码，只读检查。不要使用仅 `git diff` 而漏掉暂存内容。
5. **只说“审核改动”**：有未提交改动则按第 4 项；干净分支有明确关联 MR 则按其目标分支；仍无法确定基线时，只询问目标 MR/分支/提交，先完成仓库状态和项目约定检查，不默认全量扫描。

引用不存在、浅克隆缺基点或远端数据无法获取时，记录缺失并请求必要信息；不能退化成审完整仓库并声称完成 MR 审查。

## 先列文件，再读取内容

对上述基线先用 `git diff --name-status -M`（必要时 `-z`）枚举新增、修改、删除和重命名。此步只看路径元数据；过滤整个 `tools/`、所有 `panelDB/` 路径及其他生成数据文件后，对其余文件识别并跳过 GM 专用改动，再审查正常业务 diff 和上下文。共享函数按正常玩法调用链判断，不只凭文件名排除。不要先获取全仓库补丁再过滤。文件名作为参数正确引用并使用 `--`，不执行分支名或路径中的 shell 字符。

- `tools/` 内容不读取、不列问题。跨 tools 边界重命名只看范围内一侧，必要时用 `--no-renames` 查看该侧的新增/删除；不得以 rename 为由读取被排除内容。
- 只有 tools 或 GM 专用变更时，报告“本次变更均在排除范围内，无可审查内容”，不扩展到其他游戏。
- 变更的生产逻辑、协议、配置、依赖和构建/部署文件按实际影响审查；数值配置按入口约定仅核对消费契约。测试和文档用于核对契约。不打开生成数据（包括文本或导出文件）；生成的 `.pb.go` 按需核对协议映射，不手改。
- 定点读取改动函数、调用者、被调用者、状态机和对应测试，避免全仓库关键词扫描。删除或重命名也检查残留引用与行为缺口。
- 公共包变更可按符号引用追踪受影响游戏，验证接口契约和调用前提，不因此把所有游戏无关逻辑纳入检查。

## 需要时才补充的上下文

读取项目约定及与 diff 相关的 `cmd/gamev3 → plugin.Run → runner`、消息注册、RoomContext、结算、奖池、配置快照；不要求每个 MR 重做全项目架构调研。

依赖行为以审查版本的 go.mod/go.sum 为准。依赖变更仅对模块路径以 `git.easycodesource.com/nova/` 开头的模块按需追踪源码、比较旧新版本的相关契约；其他模块不单独阅读依赖仓库或模块缓存源码，只检查本仓库可见的使用影响，也不因未审其源码列为待补证项。

对范围内的 Nova 依赖，必要时用 `GOWORK=off GOPROXY=off GOSUMDB=off go list -m -json <module>` 定位已有缓存，只读跟踪，不主动拉取缺失依赖。不要用脏工作区或同级仓库 HEAD 替代 MR 对应版本。缺失关键链路记待补证并继续其他检查。

简要记录比较 SHA、范围内文件、tools 排除项和相关验证缺口。不切换或重置用户工作区。
